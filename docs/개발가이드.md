# 페이미터 — Android Studio 프로젝트

지금까지 쓰던 apktool 조립 방식과 다르게, 이건 **진짜 Gradle 기반 안드로이드 프로젝트**예요.
Android Studio에서 열어서 정식으로 빌드·서명하고, 플레이스토어에 낼 AAB 파일도 여기서 만들 수 있습니다.

---

## 1. 열기

1. Android Studio 설치 (없다면 developer.android.com/studio)
2. **File → Open** → 이 폴더(PayMeter) 통째로 선택
3. 처음 열면 우측 상단에 "Gradle Sync" 진행 — 몇 분 걸려요 (인터넷 필요, SDK 자동 다운로드)
4. 동기화 끝나면 상단 실행 버튼(▶) 옆 드롭다운에서 실행할 앱 선택 가능

---

## 2. 무료판 / 유료판 — 빌드 변형(Build Variant)

이 프로젝트는 **하나의 코드로 앱 2개**를 만들도록 구성돼 있어요.

- **freeDebug / freeRelease** → 패키지명 `com.paymeter.app`, 광고 레이아웃 있음
- **proDebug / proRelease** → 패키지명 `com.paymeter.pro`, 광고 없음 (2,000원 판매용)

전환 방법: 좌측 세로 탭 **Build Variants** 클릭 → active build variant에서 free/pro 선택

각 버전의 웹앱 파일은 여기 있어요:
- `app/src/free/assets/index.html` — 무료판
- `app/src/pro/assets/index.html` — 유료판

**앱 내용을 수정하고 싶으면 이 두 HTML 파일을 직접 편집하면 됩니다.** (지금까지 만든 미터기·영수증·달력·가로모드 기능이 전부 이미 들어 있어요.) 두 파일이 거의 동일하고 `const PRO = false/true`만 달라요 — 기능을 고칠 땐 두 파일 다 똑같이 고쳐주세요.

---

## 3. 폰에 바로 설치해서 테스트 (Debug)

1. 폰을 USB로 연결 (개발자 모드 + USB 디버깅 켜기) — 또는 상단 에뮬레이터 선택
2. Build Variant를 `freeDebug`로 설정
3. 상단 ▶ Run 버튼 클릭 → 자동 설치·실행

이 방식은 자동으로 디버그 서명이 되니 별도 키 없이 바로 테스트 가능해요.

---

## 4. 플레이스토어에 낼 정식 파일(AAB) 만들기

### 4-1. 서명키 만들기 (최초 1회, 절대 잃어버리면 안 됨)

**Build → Generate Signed Bundle / APK** → **Android App Bundle** 선택 → **Create new...**
- 키 저장 위치, 비밀번호, 이름(예: paymeter), 유효기간(25년 이상 권장) 입력
- **이 .jks 파일과 비밀번호를 반드시 안전한 곳에 백업하세요.** 잃어버리면 이후 업데이트를 영원히 못 올립니다.

### 4-2. AAB 빌드

같은 화면에서 → 방금 만든 키 선택 → Build Variant `free` 또는 `pro` 선택 → Finish

빌드 끝나면 `app/free/release/app-free-release.aab` (또는 pro) 생성됨 → 이 파일을 플레이 콘솔에 업로드

두 버전(free/pro) 각각 이 과정을 반복하면 됩니다. **서명키는 두 버전 다 같은 걸 써도 되고 달라도 됩니다** (플레이스토어에 별개 앱으로 등록할 거라 상관없어요).

## 5. 영수증 인증·저장 기능 (신규)

영수증 화면에 버튼 3개가 있습니다.

- **📤 인증하기** — 영수증을 PNG로 만들어 카카오톡·인스타 등으로 공유합니다. 안드로이드 공유 시트가 뜹니다.
- **💾 이미지 저장** — 갤러리(`Pictures/PayMeter`)에 저장합니다.
- **닫기**

동작 방식:
- 웹(JS)이 영수증을 캔버스에 그려 PNG로 만들고, `PayMeterBridge`(MainActivity의 JavascriptInterface)를 통해 네이티브로 넘깁니다.
- 저장은 Android 10 이상에서 **MediaStore**를 쓰므로 별도 권한 요청이 없습니다. Android 9 이하에서만 저장 권한을 씁니다(매니페스트에 `maxSdkVersion=28`로 제한).
- 공유는 **FileProvider**(`app/src/main/res/xml/file_paths.xml`)로 임시 파일을 안전하게 넘깁니다.
- 영수증마다 **인증번호**(예: `PM-260725-0C27TD`)가 찍힙니다. 날짜·금액·시각으로 생성되어 같은 영수증이면 항상 같은 번호가 나옵니다.

## 6. 구매 복원과 구글 로그인에 대해

**이 앱은 구글 로그인이 필요 없습니다.**

- 무료판/유료판을 **별도 앱으로 판매**하는 구조이므로, 사용자가 폰을 바꿔도 같은 구글 계정으로 플레이스토어에서 유료판을 재설치하면 그대로 사용할 수 있습니다. 구매 이력은 구글 계정에 귀속됩니다.
- 앱 1개에 인앱결제로 광고를 제거하는 방식으로 바꾸더라도, Play Billing이 구매 상태를 자동 복원하므로 역시 별도 로그인은 불필요합니다.
- 구글 로그인이 필요한 경우는 ① iOS와 안드로이드 간 구매 공유 ② 서버에 근무 기록 백업 ③ 구독 상품 운영 — 세 가지입니다.
- 현재 근무 기록(달력·설정)은 **폰 내부에만 저장**되므로 기기를 바꾸면 이전되지 않습니다. 나중에 필요해지면 구글 드라이브 백업을 붙이는 방식이 가볍습니다.

## 7. 나중에 AdMob 실제 광고 붙이기

지금 무료판엔 광고 "자리"만 있어요(HTML 안의 회색 배너 영역). 진짜 AdMob 광고로 바꾸려면:

1. `app/build.gradle`에서 주석 처리된 아래 줄의 `//`를 지우기:
   ```
   implementation 'com.google.android.gms:play-services-ads:23.0.0'
   ```
2. `AndroidManifest.xml`의 `<application>` 안에 AdMob App ID 메타데이터 추가:
   ```xml
   <meta-data android:name="com.google.android.gms.ads.APPLICATION_ID"
              android:value="ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY"/>
   ```
3. `MainActivity.java`에서 WebView 대신(또는 함께) AdView를 상단에 배치하는 코드 추가 — 이 부분은 실제 AdMob 계정을 만들고 광고 단위 ID를 발급받은 뒤 요청하시면 이어서 작업해 드릴게요.

## 8. 프로젝트 구조 한눈에

```
app/
├── build.gradle              ← 앱 설정, free/pro 변형 정의
├── src/main/
│   ├── AndroidManifest.xml   ← 앱 권한·기본 설정
│   ├── java/.../MainActivity.java  ← WebView를 여는 최소 코드
│   └── res/
│       ├── mipmap-*/         ← 앱 아이콘 (밀도별 5종)
│       └── values/styles.xml ← 다크 테마
│       ├── values/styles.xml ← 다크 테마
│       └── xml/file_paths.xml ← 영수증 공유용 FileProvider 경로
├── src/free/assets/index.html   ← 무료판 앱 본체
└── src/pro/assets/index.html    ← 유료판 앱 본체
```

## 9. 빌드 오류가 날 때

### "Duplicate class kotlin.*.jdk8..." 오류
이미 해결해 두었습니다. `app/build.gradle`의 아래 부분이 그 처리입니다.

```gradle
configurations.configureEach {
    resolutionStrategy.eachDependency { details ->
        if (details.requested.group == 'org.jetbrains.kotlin') {
            details.useVersion '1.9.24'
        }
    }
}
```

**왜 생기나:** AndroidX 라이브러리들이 각자 다른 Kotlin 버전을 가져오는데, Kotlin 1.8부터 `kotlin-stdlib-jdk7/jdk8`의 내용이 본체(`kotlin-stdlib`)로 합쳐졌습니다. 그래서 구버전 jdk8 라이브러리와 신버전 본체가 같이 들어오면 같은 클래스가 두 번 포함되어 빌드가 멈춥니다. 위 설정이 모든 Kotlin 라이브러리를 한 버전으로 통일해 중복을 없앱니다.

**그래도 같은 오류가 난다면:** Android Studio 상단 메뉴에서 **File → Invalidate Caches → Invalidate and Restart**를 한 번 실행한 뒤 다시 빌드하세요. 이전 빌드 캐시가 남아 있으면 수정이 반영되지 않을 수 있습니다.

### Gradle Sync가 실패할 때
- 인터넷 연결을 확인하세요 (최초 1회 SDK·라이브러리 다운로드 필요)
- **File → Sync Project with Gradle Files** 재실행
- 그래도 안 되면 오류 메시지 전체를 복사해 문의하세요

### 실행 버튼이 비활성일 때
좌측 **Build Variants** 탭에서 `freeDebug` 또는 `proDebug`를 선택했는지 확인하세요.

## 10. 참고 사항

- **minSdk 21 (안드로이드 5.0)** 이상 지원 — 사실상 모든 사용 중인 갤럭시 기기 커버
- 가로 모드, 화면 켜짐 유지(Wake Lock), 진동 알람, localStorage 저장까지 HTML 안에 이미 구현돼 있고, 이 프로젝트의 `MainActivity.java`가 그걸 실행할 수 있는 최소한의 권한(JS·저장소·자동재생·진동)을 전부 열어뒀습니다.
- 화면 회전 시 `configChanges`를 매니페스트에서 처리하도록 설정해서, **회전해도 미터기 앱이 재시작되지 않고 이어집니다** (기존 apktool 빌드보다 개선된 부분).
